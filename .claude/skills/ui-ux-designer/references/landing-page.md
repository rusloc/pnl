# Landing Page — Sketching Guide

## What this block exists to do

A landing page has **one job**: communicate what the product is and drive the visitor toward the primary call-to-action. Everything else is supporting evidence.

## Primary action

Name it explicitly before sketching. Typical landing-page primary actions:
- "Sign up" / "Create account"
- "Book a demo"
- "Start free trial"
- "Buy now"
- "Get the app"
- "Contact sales"

If the user can't name the single primary action, the landing page will fail. Push back and help them pick one. Secondary actions ("learn more," "watch video") are fine but must be visibly subordinate.

## Skeleton (the five zones)

Most effective landing pages have these zones, in this order top-to-bottom:

```
┌─────────────────────────────────────────────────────┐
│  NAV  [logo]            [links]      [secondary CTA]│
├─────────────────────────────────────────────────────┤
│                                                     │
│  HERO                                               │
│   - Headline (what this is, in plain words)         │
│   - Subhead (who it's for / why it matters)         │
│   - [PRIMARY CTA BUTTON]                            │
│   - Optional: product screenshot / visual           │
│                                                     │
├─────────────────────────────────────────────────────┤
│  SOCIAL PROOF  (logos, testimonial strip, metrics)  │
├─────────────────────────────────────────────────────┤
│  VALUE PROPS   (3-4 columns or stacked sections)    │
│                                                     │
├─────────────────────────────────────────────────────┤
│  SECONDARY PROOF  (testimonials, case studies)      │
├─────────────────────────────────────────────────────┤
│  CLOSING CTA   [PRIMARY CTA BUTTON - repeated]      │
├─────────────────────────────────────────────────────┤
│  FOOTER  (links, contact, legal)                    │
└─────────────────────────────────────────────────────┘
```

Not every landing page needs all of these, but they should appear in this order when present.

## Discoverability priorities for landing pages

### The hero must do three things in under five seconds
1. **Headline** tells the visitor *what this is* in plain language. Not a slogan. Not a pun. A sentence a 12-year-old could paraphrase.
2. **Subhead** tells them *who it's for* or *why it matters* — the "so what."
3. **Primary CTA** tells them *what to do next.*

If any of these three is missing or buried, the hero fails.

### The primary CTA is visually dominant
In the hero zone, the primary CTA button is the loudest thing. It uses the brand accent color (this is its 10% moment). It sits on its own line with whitespace around it. Secondary CTAs (if any) are outline buttons or text links — never equal weight.

### Repeat the CTA at the bottom
By the time the visitor has scrolled through value props and proof, they should hit the CTA again without having to scroll back up. This is the "closing CTA" zone.

### Above-the-fold clarity beats creativity
Clever headlines that require a second to parse lose visitors. Literal, specific language wins. "Invoicing software for freelancers" beats "Say goodbye to billing headaches."

## Common landing-page traps

- **Three CTAs of equal weight in the hero.** "Sign up," "Book demo," "Watch video" all as bold buttons. Pick one primary; demote the others.
- **Headline is a slogan, not a description.** If a stranger can't tell what you sell from the headline, rewrite it.
- **Hero visual competes with the CTA.** A giant animated illustration that pulls the eye away from the button. Either scale it down or position it to *lead* the eye toward the button.
- **Scrolljacking the hero.** Forcing the user through a scripted scroll narrative before they can act. Hated pattern; avoid.
- **Infinite testimonial carousels.** Nobody clicks "next testimonial 47 times." Show 2–4 strong ones.
- **Buried primary CTA.** If the user has to scroll to find the button on a desktop hero, the hero is too busy.
- **Marketing copy everywhere.** Corporate-speak in value props ("leverage synergies to unlock value"). Replace with concrete, specific verbs.

## What the user often forgets to think about

- **Mobile hero.** On mobile, the hero stacks vertically and real estate is scarce. The headline-subhead-CTA must still fit on one screen. Sketch the mobile version separately.
- **Empty/loading states.** If social proof logos load late, don't let the layout shift. Reserve the space.
- **The "back" path.** If visitors click the CTA and then decide to go back, what do they see? Landing pages are often revisited.

## Output checklist

When sketching a landing page, your response should include:
- The named primary action
- The zoned skeleton (ASCII, SVG, or list)
- Explicit placement of the CTA (hero + closing)
- Desktop vs. mobile treatment if relevant
- A short list of what to cut if the user's current draft is too cluttered
