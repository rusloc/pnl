# Cross-track parity rules (A · B · C)

> Status: accepted (main agent, 2026-10-23, from hunter's parity audit). Applies to Track A (`fabric-app/`), Track B (`pbi-report/ACME Unified PnL/`) and Track C (`js-report/`). All three are shown on vosk.dev/work, so the same selection must read the same in every track.
> Track B is the reference for copy and layout unless a rule below says otherwise. Related: `docs/design/period-picker-v2.md`, `docs/design/kpi-card-v2.md`, ADR-0004, ADR-0007.

## Numbers

1. **Analysis comparison = C-40 in every track:** Compare A, else Compare B, else Prior year. No separate Analysis toggle (Track A's `analysisCompare` goes). Profitability's "vs …" uses the same comparison.
2. **Hide empty lines (M-22)** rounds in the selected units (millions or thousands), on the columns that are visible.
3. A test must never assert a known bug. Fixtures captured before a model fix are re-captured after the fix is published.

## Defaults

4. **Profitability breakdown default = Region** for every company (F-21, ADR-0007 §3a).
5. **Statement opens collapsed** with Expand all / Collapse all (M-20, M-21).

## Copy

6. **Separator " - "** in every header, rail, picker and pop-up text. " · " is not used anywhere in UI copy. The en dash "–" stays inside ranges ("Jan – Sep").
7. **Period summary sentence** always starts with "Showing" (panel, rail tooltip, applied-filters Period row, expanded-rail summary). Nothing covered → exactly `Showing no closed month yet` (no time-view tail).
8. **Rail Versions summary** with no comparison: `Actual only` (Track B wording).
9. **Notice rows** in the applied-filters pop-up: one row per notice, labelled as Track B does (`Cut-off`, `Forecast`, `Prior year`, `History`, `Allocation`, `Eliminations`), notice text copied from Track B's `Notices` / `_Notice Row`; no row at all when none applies (no "None for this selection").
10. **Slice values** (regions, channels, …) are listed in the dimension's `sort_order`, not alphabetically, in rail summaries and the pop-up.
11. **Statement rows** use Track B's numbered top level (`01. GROSS REVENUE` … `29. NET MARGIN %`, `dim_pl_row[line_display]`); accounts keep their names.
12. **Column-group titles** follow Track B: `<window> - <version>`, e.g. `YTD Sep 2026 - Actual`, `Full year 2026 - Budget`.
13. **Subtitles and captions are built from the selection**, never hard-coded (statement footnote, Vitals (formerly Key figures) caption "Changes vs <Compare A> and <Compare B>, same months", Profitability subtitle = the period summary without "Showing" + currency and units).
14. **Units buttons** show the selected currency's symbol (`$m / $k`, `€m / €k`, `£m / £k`).
15. **KPI arrows** show the direction of the change (▲ up, ▼ down); colour shows favourable / unfavourable. The legend says exactly that: "▲ up / ▼ down - green = favourable, orange = unfavourable" (" - " per rule 6).
16. **Info pop-ups** use `docs/ADD/features/info-popovers.md` verbatim; the `{comparison}` placeholder is lower case ("from budget", "from latest estimate"). Superseded on the redesigned views by rules 18–21 (2026-10-27).
17. **Compare = None:** the column group is dropped (Tracks A and C); Track B keeps an empty group with "none" (native limit, accepted).

### ADR-0012 / P&L views redesign v4 (2026-10-27)

18. **ⓘ per card and per panel:** every Vitals card and every Analysis / Profitability panel has one ⓘ; it shows the name, what it shows and the formula or sub-metrics (the card face keeps title · value · Δ rows · status chip only). Track B: hover tooltip page; Tracks A and C: pop-over on click / hover.
19. **One How to read per view** (Vitals, Analysis, Profitability) holds the reading guide; no prose strips on the canvas.
20. **Pager:** Analysis and Profitability have two pages each, switched by ‹ › with the text "n / 2" next to the tabs; the P&L statement and Vitals have one page.
21. **Glass = solid panel in Track B:** frosted-glass panels of the HTML design are solid white panels with the Ledger border in Power BI (native limit, accepted).

Track A (2026-10-27, `fabric-app/`, see `docs/ADD/features/track-a-pnl-views.md`): 18 — one ⓘ per Vitals card and per panel (`components/info-popover.tsx`; copy = `dim_pl_info` verbatim for panels, `dim_kpi` definition + `KPI Info Sub` for cards, source line per card); 19 — one "How to read" per view in the tabs row (`components/how-to-read.tsx`, lines after Track C's `view-copy.ts`, opening with the selection sentence); 20 — `Pager` next to the tabs on Analysis / Profitability, ← → keys page too, each view remembers its page; 21 — glass dialogs with the `@supports` solid fallback (`components/glass-dialog.tsx`), one layer open at a time, Esc / outside click / × close, Tab trapped, focus returned.

## Accepted platform differences

- Track B: open months under Actual stay selectable (shown "not closed yet"); no Escape / radiogroup keys in flyouts; no notice-count badge on the funnel; shading in a strip under the month grid; Hide empty lines hides only rows whose values are all blank (a leaf that rounds to 0.0 in every column stays visible: doing rule 2 natively would make every column measure evaluate all the others and undo the ADR-0008 speed-up).
- Track C: "Copy link" on the tabs row (F-37).
- Nordmark Exec (2026-10-30, ADR-0013 (l) "Doc alignment", E-53 / E-91): **the FY row of the period picker at Year** — the JS flavour hides the FY row and offers the two FY items (`FY2025`, `FY2026 · to date`) as the item chips; the Power BI flavour keeps the FY row (`menu_item_fy`), which then drives the single Year chip, because a slicer cannot select a value on behalf of another slicer. Same items, same windows, same header; only the picker rows differ.
- Nordmark Exec (2026-10-30, ADR-0013 (l), E-103): **the Category dropdown's closed-state wording** — the JS shows "All categories" in the closed dropdown and as the clearing option; the Power BI dropdown slicer shows its native "All" when nothing is picked. Same semantics (no pick = All, all 9 ticked = All), same header segment, same numbers.
- Mirelo Sales (2026-11-01, owner changes, `.sync/2026-11-01-mirelo-sales-changes.md`; Power BI side by bip):
  - **Pop-up glass without blur:** the Power BI pop-ups (Filters panel, How to read, ⓘ tooltip page, detail pages, list windows) share one style: `#F4F3F0` at 90 % opacity with a 1 px `#1A1A1A` border, 12 px corners and a container shadow (`#111111` at 26 %, 0 / 18 px, blur 44 since 2026-11-04; the JS second, tight layer `0 2px 6px` does not exist); Power BI has no backdrop blur. Change 20 (2026-11-02, "~10 % more transparent") is not applied: at 85 % the charts under the Filters panel read through its text (render-checked); the JS is at 32 % with a 28 px blur. The masks behind the detail pages and list windows are `#404040` at 32 % (JS: 20 % + a 6 px blur).
  - **Calendar (2026-11-02, change 11):** both flavours pick a range of closed months (a month, a quarter, a year or a custom range) and drop Week, QTD, YTD and R12M. Power BI uses one hierarchy slicer Year > Quarter > Month (a custom range = click the first month, Ctrl+click the last; the window runs from the first to the last pick), not the JS mode row, year stepper and tile grid; same windows, same filter line and Showing sentence.
  - **Free ranges are computed in Power BI (change 11, "truth beats parity"):** returning %, time to cash, cycle time and days between loans show real values for every range, because the model holds the loan and client grain; the JS shows n/a for ranges that are not a month, a quarter, a year to its end or 12 months (`window-stats.parquet`).
  - **Detail window:** Power BI keeps the drill-through pages for loans and the client card (ADR-0011 accepted difference, unchanged), restyled as the centred 1120 × 640 window over the mask; the report is not visible under it. The C11 and P13 lists (changes 28-29) are overlays on the report page itself (same window and mask, report visible under it): select a row, then **Show clients ↗** / **Show overdue loans ↗** (with no row selected the list holds all channels / products), where the JS opens the window on a row click. Every list holds all rows and scrolls; **no pager and no CSV export** (change 31; the note in each window points to the custom JS version). No Escape or focus trap.
  - **Filters panel:** no funnel icon on the Filters button (no built-in funnel glyph); the selected tile is Power BI's dark default; Filters and How to read can be open together (a view change closes Filters); **Reset** looks disabled at the defaults (grey text and outline) but stays clickable (Clear all slicers returns the latest closed month, Budget, All markets); the panel is 420 × 514 as the JS (2026-11-04; it was 440 wide); it closes with the × at its top right (the USER's icon tile of 2026-11-03, finished to the JS × on 2026-11-04) or a second click on the Filters button (its open-state twin), not with Escape or a click outside. "Details →" inverts on its own hover, not on card hover.
  - **Funnel labels (changes 15, 23):** L8 is stacked columns on the scale of Started (ink = reached the next stage, yellow `#FFD54A` = did not), the JS draws bars with a yellow line; the "52% of leads - +1.1pp vs PY" text of L8 and the "x% of leads" text of C8 sit in the tooltip (hand-written data-label details do not render in Power BI); C8 stage names come from `dim_funnel_stage` (Lead, Submitted, Credit approved, Disbursed; JS: Leads, First application, First approval, First loan).
  - **P12 bubbles (change 17):** labels on all five products (the JS labels the three largest and the worst); the card's market pick shows no tile selected while it follows the page region.
  - **Leaderboard sort (change 33):** native header sort; every column sorts on a number whose dynamic format string shows the Track C text (Status: rank On target 3 / Close 2 / Behind 1 / n/a 0); n/a sorts last descending but first ascending (JS: last both ways). The Ramp tag sits in its own TAG column (a table cell holds one value; JS: a tag beside the name), and a narrow invisible agent-code column keeps apart the agents that share a name (20 names are used twice in `dim_agent`).
- Mirelo Sales (2026-11-02, Power BI = JS fix-up; bip): tables, titles, ⓘ copy, heat colours and the C5 parity rows checked against the Track C engine output (`tests/control-totals.dax` T-M9, T-P). Remaining differences:
  - **Comparator column headers:** Power BI headers are static, so the column the JS calls "vs Budget" / "vs PY" (O9) or "vs quota" / "vs PY" (L13) reads **VS BUDGET / PY** and **VS QUOTA / PY**; the cells follow the picker as in the JS.
  - **ⓘ sub-values:** one paragraph, items as "Label: value" joined by "; " (the tooltip text is a button, which shows no line breaks); JS: one line per item. C11 / P13 formulas and the Clients / Portfolio How to read lines name the Power BI interaction (select a row, then Show clients ↗ / Show overdue loans ↗); the How to read Filters line drops the JS sentence on n/a ranges (Power BI computes them, see Free ranges).
  - **Legends that the JS builds from the selection:** O6 says Actual (JS: the window, e.g. Sep 2026); O7 and P8 name the series by slot (Anchor quarter, Previous quarter, …; JS: Q3 2026, Q2 2026, …): a legend item cannot be computed. R9 stays columns against a Budget line without a legend (JS: bullets with a Revenue / Budget legend); P12 has no legend (JS: Product, worst 30+ DPD).
  - **R13 total row:** the Market cell is blank (JS: All) and the status chip on the total row has no colour fill.
  - **Open, not accepted (data layer, #handoff ginee):** names that come from the dimensions: channel App organic (JS App) in O6 / C7 / C11 / R12 and the lists, stream Interest income (JS Interest) in R8 / R13, loan status names in the lists (30-59 days past due; JS 30–59 DPD).   - **Story callouts:** plain 8 pt semibold text, no box. Power BI has no dashed event marker (O8 has a categorical month axis, which takes no x constant line), and the callout keeps its place in the chart; it does not move with the event month or hide when the month leaves the 13-month range (as before). The chart alt text names the event in both flavours.
  - **Canvas:** Power BI keeps a fixed 1440 × 810 page with Fit to page and the wallpaper in the ground colour; the JS board grows taller to fill the popup. The iframe aspect the host should use is in `pbi-report/Mirelo Sales/README.md`.
