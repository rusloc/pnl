## How the measures work

- **Window (2026-11-02, change 11).** The pickers are disconnected tables: `param_anchor_month` (the calendar: closed months, with
  the hierarchy Year > Quarter > Month for the Filters panel slicer), `param_comparator` (Budget / Prior year), `param_market`
  (All markets / PL / RO / PT). The picked months set the window: `_Win Start` = the first, `_Win End` (= `_Sel Anchor Index`) = the last
  picked month, so a range is always contiguous; no pick = the last closed month. `_Period Kind` (month / quarter / year / range) and
  `_Period Label` name it as Track C periodKind / periodLabel. Every visible window measure is `CALCULATE ( [_Base], REMOVEFILTERS ( dim_month ),
  month_index in the window, KEEPFILTERS ( market ) )`; the PY twin shifts the range by 12 months. Period-end measures (portfolio, MRR,
  subscribers) use the last month of the window. Distinct counts and medians (returning %, time to cash, days between loans) compute
  for any range from the loan grain, so Power BI shows real values where Track C shows n/a (parity-rules, accepted difference).
- **Base measures** (`0 Base`, hidden) respect every filter; charts by month (`7 Trend`) evaluate them per `dim_month` row for the 13 months
  ending at the anchor.
- **EUR.** Actuals use the EUR columns of the data (`principal_eur`, `amount_eur`) or the `*_eur` columns derived on load in Power Query
  (`fact_loan_month`: local / ACTUAL_AVG rate of month x currency). Budget amounts use `fact_target[target_eur]` (local / BUDGET rate,
  derived on load). Constant currency (bridge FX step) uses `fact_loan[principal_eur_bud]`.
- **Tiers.** Tier 1 = the four Overview metrics and their comparators; Tier 2 = KPI band of views 2-5; Tier 3 = chart and table support;
  Design = text, titles and colours; Engine / Base = hidden plumbing.
- **Status** (design-tokens §6): counts / amounts good >= 0 %, watch -5 % to 0 %, off < -5 %; ratios good >= 0 pp, watch -2 to 0 pp;
  risk ratios good <= 0 pp, watch 0 to +0.5 pp; hours good <= 0, watch 0 to +0.5 h; attainment from `param_thresholds` (>= 100 % good,
  95-100 % watch). Rounded to the displayed precision before the band test. `n/a` when no comparator exists.
- **No budget in the data** for: approval, take-up, time to cash, returning %, repeat share, 90+ DPD, 30+ by count, vintage, roll rate,
  cost of risk, interest alone, fees alone, MRR, subscribers, channels. Those cards show `vs Budget n/a` when Budget is selected.
- **Heat matrices (2026-11-02, change 32).** L10, C9 and P9 share one scale: `Heat Level X` = (value - min) / (max - min) over every shown
  cell of the grid (built explicitly: Power BI evaluates a field-value colour per cell with that cell as an outer filter, so ALLSELECTED
  would see one cell), `Heat Fill X` interpolates grey #DEDDD8 -> yellow #FFD54A -> orange #F28C28 -> red #C0392B, `Heat Ink X` is white
  from 0.8.
- **KPI rows (2026-11-01, Track C `kpiRows`).** The eight KPI cards whose metric has a Budget (L1 Loans, L2 Principal, L3 Avg
  ticket, C1 New clients, P1 30+ DPD %, R1 Revenue, R3 Interest + fees, R4 Interchange) draw "vs Budget" and "vs PY", Budget
  first; the status chip follows the comparator picker and falls back to the other row when that one is n/a. The other 16
  KPI cards draw one row (vs PY, or their fixed reference: vs PY cohort, vs PY vintage, vs 100%). Info button top-left,
  title at x 30 on every hero and KPI card.
- **Table cells = Track C text (2026-11-02, Power BI = JS fix-up).** The O9, L13, C11, P13 and R13 tables and the L10 / P9 cells
  bind display measures (`O9 Loans`, `Agent Principal Shown`, `P13 Bal 1-29`, `R13 Δ %`, …): the value stays a number (header
  sort), and a dynamic format string shows the hidden `_T <name>` text, written as Track C formats it (fmtCount 11.7k, fmtEur
  €3.3m / €580k, fmtPct, glyph deltas ▲ +1.5%, n/a). The literal sits in both format sections, so a negative value gets no extra
  minus. Leaderboard numbers add `_Agent Tiebreak` (attainment x 1e-7, sort order x 1e-16) so equal values keep the engine order;
  n/a sorts last descending (Δ -2, attainment just below 0, Status rank 0).

VAR _actual       = [_Principal EUR]

VAR _budget       = [_Principal Budget EUR]

VAR _mix_sum      =

        CROSSJOIN (
            VALUES ( dim_month[month_key] )
            ,VALUES ( dim_market[market_code] )
            ,VALUES ( dim_product[product_code] )

         VAR _cell_bud    = [_Principal Budget EUR]

                 ,[_Principal EUR at Budget FX]
             )

    SWITCH (
        _step
        ,"BUDGET"
            ,_budget
        ,"VOLUME"
            ,( _loans - _loans_bud ) * _ticket_bud
        ,"MIX"
            ,_mix_sum - _loans * _ticket_bud

            ,_actual_cc - _mix_sum
        ,"FX"
