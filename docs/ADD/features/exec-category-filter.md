## 2. Per-card category applicability (E-30 … E-41)

### 2.1 Which facts carry `category_code` (evidence: `manifest.json`, `generate.py` "assemble tables", `verify.py` integrity block)

| Fact | Grain | `category_code` | Feeds |
|---|---|---|---|
| `fact_sales_week` | week × selling site × category | **yes** | gross, markdown, returns, net sales, units, COGS, **`back_margin_alloc`**, `is_lfl` / `is_lfl_as_ly`, channel mix |
| `fact_budget_week` | week × selling site × category | **yes** | every Budget value incl. LFL budget and plan mix |
| `fact_inventory_week` | week-end × location (stores, ONLINE, 2 DCs) × category | **yes** | cover numerator, GMROI denominator, sell-through opening units |
| `fact_forecast_week` | week × selling site × category | **yes** | cover denominator and the cover target weights |
| `fact_availability_week` | week × store × category | **yes** | availability (ranged per category = `top500_skus` share of 3,500 SKU-days per store-week) |
| `fact_receipts_week` | week × selling location × category | **yes** | sell-through receipts |
| `fact_supplier_income_week` | week × supplier | **no** | source of back margin — but the card reads `back_margin_alloc` (above), not this fact |
| `fact_po_week` | week × supplier | **no** | Supplier OTIF |
| `fact_opex_week` | scenario × week × cost type × site / central | **no** | the OpEx side of EBITDA (ACT and BUD) |
| `param_target` | KPI × (ALL or category) | category rows for **WEEKS_OF_COVER, GMROI, SELL_THROUGH** (= `dim_category` columns); **ALL only** for AVAILABILITY (0.97) and SUPPLIER_OTIF (0.95) | targets |

Two findings worth stating because they change what "approximation" means here:

- **Back margin is exact per category in this dataset.** `generate.py` fixes `BACK_IC` per week × category first, allocates it to site cells by COGS share (`fs['back']`) **and** to suppliers of that category (`si_c = sch.c.values[si_s]`, `alloc(si_i * NC + si_c, …, BACK_IC)`). So Σ `back_margin_alloc` per week × category = Σ supplier income of the suppliers whose `primary_category_code` is that category, to 1e-10 (ET-07 asserts it; re-checked 2026-10-30: max diff 2.3e-10). The card never needs the supplier fact.
- **`dim_supplier.primary_category_code` is one-to-one in the data** (every supplier has exactly one category and all its income and PO lines sit there), so an OTIF-by-category reading *would* be exact on this dataset. It stays an approximation in the real-world sense the USER named, and the fact itself has no category key — see the OTIF verdict.

### 2.3 Targets under a category selection (E-102) — one principle

*Note (ruling 2026-10-30): the per-category status chips are arithmetically true but not story-tuned — ginee's proof shows Weeks of cover Off track for 5 of 9 single categories at W43 and GMROI below its own target for 7 of 9. Accepted as is; the W43 story is the All view.*

The target of a ratio card under a pick is the **denominator-weighted mean of the category targets over `K`**: cover → `forecast_cogs` weights (existing formula), GMROI → average on-hand cost weights (new), sell-through → (opening + receipts) weights (formal, all 0.62). Cards with an ALL-only target (availability 0.97; OTIF, moot) keep it. At All, every card keeps its `param_target` ALL row, so no All number moves (ET-02 / ET-22 hold). A single category's target is its `dim_category` row.

### 2.4 Counts and dot under a category selection (E-103)

Over the rated cards (status ≠ N/A), as built (E-95 pattern; README open point 10). With any pick in FY2026 at ALL / NL / BE: at most **10** rated (EBITDA and OTIF N/A), **9** when the pick has no seasonal category; ONLINE: 8 / 7 (availability and LFL N/A). FY2025 items: 2–4 (cover, availability, sell-through in season, GMROI from W52). `status.count_na` grows accordingly; the three count pills stay as built (no n/a pill). n = 0 → grey dot (E-95 guard). The dot **follows** the category pick like it follows Region (it is a data-scope filter, not an attribute filter — E-26's "filters ignored" means Group / Lever / Owner). The status-line summary "n of 12 metrics · picks" and the Filters badge count **attribute picks only** — unchanged; the category pick shows in the header line (§3). Decided 2026-10-30: the badge does not count the category, as it does not count Region.

## 4. JS flavour (`js-exec/`, nerd) — describe, don't build

- **URL key `cat`** (E-62 amended): value = `dim_category.category_code` list, **comma-separated like the attribute picks** (`cat=ELEC,TOYS`; `URLSearchParams` serialises the comma as `%2C` — do **not** use `+`, which `URLSearchParams` decodes as a space). Parse with the existing `picksOf` shape: `z.string().max(128).catch('')`, split on `,`, keep only codes present in `d.categories` (manifest-driven, case-sensitive like `group=B1`), **normalise to `sort_order` order and deduplicate**; an empty or fully-invalid list, or **all 9 codes**, = All → key **absent**. Serialise after `r`, before the attribute keys: `?i=FY2026-P10&c=ly&r=nl&cat=ELEC%2CTOYS&group=B3` round-trips byte-identical; `?cat=toys,ELEC,ELEC,FOO` → `cat=ELEC`; `?cat=FOO` → default (no key). No interaction with `i` / `c` normalisation (no snap). `Selection` gains `categories: readonly string[]` (empty = All); `DEFAULT_SELECTION` unchanged otherwise.
- **Engine:** `Scope` becomes `{ region, categories }`; every cube sum in `metrics.ts` takes a category mask (the cube is already week × group × category, E-83 — no data change, no new file). EBITDA and OTIF return `null` when `categories.length > 0`; sell-through runs on `K ∩ seasonal` and returns `null` when empty; GMROI target = AOH-weighted `gmroi_target` over `K` when a pick is active, else 2.5; cover target = the existing weighted formula on `K`; mini stats restricted to `K`. Status via the existing N/A path (`code === undefined → 'na'`).
- **Filters menu:** a `Category` row between Region and the attribute groups: a `<select multiple>`-equivalent dropdown (names only, menu order), placeholder `All categories`, a per-item check; Reset clears it with everything else. `view.ts header()` appends the segment of §3. Badge unchanged.
- **Tests:** control rows of §6 through the same `control-totals.test.ts` path (scope string `ALL#ELEC` parsed into region + categories); `url-state.test.ts` cases of ET-36; a view test for the three header forms.

## 5. PBI flavour (`pbi-report/Nordmark Exec/`, bip)

- **Slicer** `menu_param_category` on `dim_category[category_name]` (already `sortByColumn: sort_order`): **dropdown**, multi-select, *Select all* off, single-select off, title `Category`, placeholder shows "All" when nothing is picked (Power BI shows "All" by default). Placed in `menu_panel` under Region. `dim_category` already joins the six category facts single-direction, so sales, budget, inventory, forecast, availability and receipts filter natively; **do not** relate `dim_supplier.primary_category_code` to `dim_category` (that would make OTIF silently follow the approximation) and do not relate `fact_opex_week`.
- **The trap:** the base measures on `fact_po_week` and `fact_opex_week` are unrelated to `dim_category`, so under a pick they would silently return the **All** value. Guard explicitly: `_Category Active = ISFILTERED ( dim_category[category_name] ) && COUNTROWS ( VALUES ( dim_category[category_code] ) ) < COUNTROWS ( ALL ( dim_category[category_code] ) )` (hidden, folder 9 Engine) — **`ISFILTERED` alone is not enough: nine ticked names must behave like no selection** (ruling 2026-10-30: all 9 = All — no N/A, ALL targets, no header segment); the category facts are then unrestricted anyway, so only the guard, `GMROI Target` and `_Category Label` need the count test. Then `IF ( [_Category Active], BLANK (), <expr> )` on the base measures `OpEx Amount` (every scenario / cost type), `PO Lines Due`, `PO Lines OTIF`, `Suppliers Below 85`, `OTIF Target` **and** on every EBITDA measure (`EBITDA`, `EBITDA Bud`, `EBITDA PTD`, `EBITDA Bud PTD`, `Card Prev EBITDA`, `EBITDA Margin %` and its Bud) — blanking OpEx alone is not enough, because `Total Margin − BLANK ()` evaluates to Total Margin. Everything downstream (status, bars, Δ, ⓘ) already renders BLANK as N/A (E-95); the Δ label measure gets the `n/a by category` text and the `Info EBITDA` / `Info SUPPLIER_OTIF` texts the one-line note of §3.
- **Measures that need no change** (they filter natively): every sales / budget / inventory / forecast / availability / receipts sum, `Cover Target Wks` (already `SUMX ( forecast_cogs × RELATED ( cover_target_wks ) ) ÷ Σ forecast_cogs`), status, counts, dot, bars, LY / previous windows (sort_index bounds from `dim_item` are category-independent), the `Card …` and `Info …` layers. **Change:** `GMROI Target` (today the constant 2.5) → `IF ( [_Category Active], DIVIDE ( SUMX ( VALUES ( dim_category[category_code] ), [GMROI Avg On Hand Cost] * CALCULATE ( MAX ( dim_category[gmroi_target] ) ) ), [GMROI Avg On Hand Cost] ), 2.5 )`; `Sell Through Target` may stay 0.62; sell-through measures already restrict to `is_seasonal` (verify the `Sell Through %` measure keeps that restriction when `dim_category` is filtered — a pick of non-seasonal categories must return BLANK, not a division by zero); the `gmroi.<CAT>` / `sell_through_pct.<CAT>` ⓘ mini-stat text iterates `VALUES ( dim_category )` so it shrinks to the pick.
- **Header:** `_Category Label` = `SWITCH ( TRUE (), NOT [_Category Active], "", COUNTROWS ( VALUES ( dim_category[category_name] ) ) = 1, " · " & SELECTEDVALUE ( dim_category[category_name] ), COUNTROWS ( … ) = 2, " · " & CONCATENATEX ( VALUES ( dim_category[category_name] ), dim_category[category_name], " & ", dim_category[sort_order] ), " · " & COUNTROWS ( … ) & " categories" )`, appended to the region segment of the header measure. Title, period line and `menu_showing` untouched.
- **Bookmarks / scrim:** the four layer bookmarks (`bm_filters`, `bm_how`, `bm_more`, `bm_close`) are display-only (no data), so opening / closing the menu never resets the category slicer; conceal in place is an SVG state, not a bookmark. **Reset = *Clear all slicers*** clears the category slicer too → All (the saved report state has no category picked). The dropdown's list renders in Power BI's overlay above `layer_scrim` and `menu_panel` — expected; close it before taking parity screenshots. The dropdown slicer must be a real slicer (not a visual-level filter) so *Clear all slicers* reaches it.
- **Tests:** `tests/control-totals.dax` gets T-N1 blocks for the sampled category scopes (§6, set the scope with `TREATAS ( { "Electronics", "Toys & leisure" }, dim_category[category_name] )` on top of the region code), one T-N3 block for the three header forms and the N/A texts, one T-N7 row that the EBITDA and OTIF ⓘ show the N/A note.

## 6. Control-total plan (ginee) — sampled key set

**Why sampled:** 2^9 − 1 = 511 category selections × 87 item keys × 4 regions ≈ 178 k cells is 25× today's file and the DAX side already runs 2 h 10 min for 34 k rows.
